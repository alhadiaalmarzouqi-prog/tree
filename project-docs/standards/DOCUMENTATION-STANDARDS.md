# DOCUMENTATION-STANDARDS — معايير توثيق المشروع

**الحالة:** معتمدة كمسودة إجرائية، وتحتاج موافقة المالك.

## 1. الهيكل الدائم
| المسار | المحتوى | المالك |
|---|---|---|
| `CLAUDE.md` | نقطة الدخول الإلزامية للوكلاء (قصيرة، تشير ولا تكرر) | المالك |
| `project-docs/analysis/` | تحليل المواصفة: المتطلبات، التعارضات، القرارات المعلقة، التتبع | مرحلة التحليل |
| `project-docs/standards/` | معايير التوثيق، وتنظيم الكود، وقواعد الوكلاء | المالك |
| `project-docs/handoffs/` | ملفات التسليم بين الوكلاء | الوكيل المنفذ |
| `project-docs/` (لاحقاً) | `MASTER-ARCHITECTURE.md`، `DATABASE-DESIGN.md`، `RELATIONSHIP-ENGINE.md`، `SECURITY-AND-PRIVACY.md`، `API-SPECIFICATION.md`، `UI-UX-SPECIFICATION.md`، `TEST-STRATEGY.md`، `DECISIONS.md`، `PROJECT-STATUS.md`، `KNOWN-ISSUES.md`، `CHANGELOG.md`، `phases/`، `execution/` | بعد موافقة التحليل |

## 2. قواعد الكتابة
1. كل متطلب له معرّف ثابت (FR، PRV، SEC، GOV، TECH، DATA، PERF، OPS، TST، SCOPE، PLAN، DR، CG، RISK). لا يُعاد استخدام معرّف أو تغيير معناه.
2. تُفصل الحقائق المأخوذة من المواصفة عن التوصيات بوضوح: التوصية تُكتب تحت عنوان "التوصية التقنية" فقط.
3. أي افتراض يُكتب تحت عنوان "افتراض" ويُحال إلى قرار.
4. لا يُكتب "مكتمل" أو "مُنفّذ" أو "مُختبر" إلا بدليل من تنفيذ حقيقي يُذكر مساره ونتيجته.
5. لا تُكتب أرقام أو نتائج اختبار وهمية أو مقدّرة كأنها فعلية.

## 3. الإصدار والتغيير
- كل وثيقة معتمدة تحمل رقم إصدار في سطرها الأول بعد العنوان (مثل: `الإصدار 0.1 — مسودة`).
- أي تغيير على وثيقة معتمدة يُسجَّل في `CHANGELOG.md` بالتاريخ والسبب والمعرّفات المتأثرة.
- تغيير قرار معتمد يتطلب: تسجيل الأثر في `DECISIONS.md`، وموافقة المالك، وتحديث كل وثيقة متأثرة.
- لا يُعدّل المسار المعتمد في `DECISIONS.md` بصمت.

## 4. التوافق مع المواصفة
- كل وثيقة تطوير تبدأ بالإحالة إلى معرّفات `REQUIREMENTS.md` التي تغطيها.
- `TRACEABILITY-MATRIX.md` هو المرجع لربط المتطلب بالتصميم والمرحلة والاختبار.
- عند ظهور تعارض بين وثيقة ومواصفة، تُعتمد المواصفة أو قرار المالك، ويُسجَّل التعارض في `CONFLICTS-AND-GAPS.md` أو `KNOWN-ISSUES.md`.

## 5. اللغة والتنسيق
- الوثائق بالعربية، مع المصطلحات التقنية بالإنجليزية كما هي (مثل PostgreSQL، RLS).
- المعرّفات بالإنجليزية وأرقامها ثلاثية (FR-001).
- جداول Markdown للمتطلبات والقرارات، وعناوين مرقّمة للأقسام.
