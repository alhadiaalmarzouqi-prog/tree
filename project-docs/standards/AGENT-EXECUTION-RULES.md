# AGENT-EXECUTION-RULES — قواعد تنفيذ الوكلاء

**الحالة:** ملزمة لكل وكيل ذكاء اصطناعي يعمل على المشروع.

## 1. نطاق الجلسة
1. كل مرحلة تُنفَّذ في محادثة منفصلة جديدة.
2. كل مرحلة لها نطاق واضح، ولا يجوز تنفيذ مرحلة غير المسندة.
3. بعد إكمال المرحلة يتوقف الوكيل ولا يبدأ التالية تلقائياً.

## 2. القراءة قبل التنفيذ
1. يقرأ `CLAUDE.md` أولاً.
2. يقرأ ملف المرحلة المسندة إليه فقط.
3. يقرأ الوثائق المرجعية المذكورة في ملف المرحلة فقط.
4. يفحص الكود الفعلي في المستودع قبل أي تعديل.

## 3. المنع
- ممنوع اختلاق ملفات أو دوال أو جداول أو نتائج اختبارات أو حالات تنفيذ.
- ممنوع تغيير معمارية معتمدة أو قاعدة عمل معتمدة دون موافقة المالك.
- ممنوع اتخاذ قرار معلّق في `DECISIONS-REQUIRED.md` بالنيابة عن المالك.
- ممنوع تعديل ملفات خارج نطاق المرحلة أو الكتابة فوق عمل موجود دون فحص.
- ممنوع تسمية المرحلة مكتملة دون تشغيل الاختبارات ونشر نتائجها الفعلية.
- ممنوع إضافة بيانات وهمية كدليل على النجاح.

## 4. متطلبات الإكمال
1. تشغيل الاختبارات المطلوبة وتسجيل نتائجها الحقيقية، بما فيها الفاشلة.
2. تحديث `PROJECT-STATUS.md` و`CHANGELOG.md`، وتحديث `KNOWN-ISSUES.md` عند الحاجة.
3. تحديث `DECISIONS.md` فقط عند وجود قرار معتمد من المالك.
4. كتابة تقرير تنفيذ في `execution/` يتضمن: الملفات المنشأة والمعدَّلة، نتائج الاختبارات، المهام غير المنجزة، الموانع.
5. تحديث `handoffs/NEXT-AGENT.md` بملف تسليم يشير إلى الوثائق لا إلى سجل المحادثة.

## 5. المراجعة والاعتماد
- المرحلة لا تُعتمد لمجرد قول الوكيل إنها مكتملة.
- يجب أن تكون المراجعة المستقلة ممكنة قبل الاعتماد (DR-31).
- إذا تعذر إكمال المرحلة يُبلَّغ عن الموانع بدقة دون وسم المرحلة مكتملة.
- القرار النهائي بالاعتماد للمالك.

## 6. الإبلاغ
- التقرير يذكر ما تم فعلاً، وما لم يتم، وما لم يُختبر، بوضوح.
- أي افتراض يُذكر صراحةً.
